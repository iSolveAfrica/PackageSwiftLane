# Swift Lane UI — developer guide

This guide explains how the approved design (the Claude artifact "Swift Lane UI
Redesign") is implemented in this PHP code base. Read it before adding or
changing a page.

## 1. Where things are

| Path | Purpose |
|---|---|
| `docs/handover/artifact-source/*.dc.html`, `swiftlane.css`, `canvas.json` | The approved design, verbatim. The visual reference for every page. |
| `assets/swiftlane/swiftlane.css` | The design system stylesheet (copy of the artifact's). Do not restyle it. |
| `assets/swiftlane/app.css` | Runtime-only additions (toasts, dialogs, validation, print). |
| `assets/swiftlane/pages/<Board>.css` | The page-specific `<helmet><style>` of each artboard, verbatim. |
| `assets/swiftlane/swiftlane.js` | Runtime: theme, menus, dialogs, tabs, client-side filters, `SL.post()`, forms, toasts. |
| `views/sl/inc/shell_start.php`, `shell_end.php` | The application shell (header, rail, sidebar). Fed by session, settings and `helpers/sl_nav.php`. |
| `views/sl/inc/plain_start.php`, `plain_end.php` | Shell-less wrapper for auth, public and print pages. |
| `views/sl/pages/<Board>.php` | One template per artboard, generated by `scripts/sl_convert.py` then bound to real data by hand. |
| `views/sl/data/<topic>.php` | Data providers: functions returning the `$d` array a template renders. All SQL lives here or in `helpers/`. |
| `ajax/sl/*_ajax.php` | JSON endpoints for the new pages (`sl_json()`), guarded by `require_login()` / `require_permission()`. |
| `helpers/sl_routes.php` | Artboard name → PHP URL. Templates link with `sl_route('Board')`. |
| `helpers/sl_nav.php` | Navigation registry with permission gates and live counters. |
| `helpers/sl_view.php` | `sl_render()`, `sl_gate()`, `h()`, `sl_v()`, `sl_money()`, `sl_date()`, `sl_pager()`, `sl_rows()`, `sl_tableExists()` … |
| `helpers/sl_charts.php` | SVG paths/points/heatmap helpers for the dashboard charts. |
| `migrations/*.sql` | Idempotent schema upgrades (guards on information_schema; ledger `cdb_schema_migrations`). |
| `database/` | Consolidated upgrade, fresh install schema, rollback and README for operators. |

## 2. Anatomy of a page

```php
// <page>.php (root controller; keep the legacy file name when one existed)
require_once 'loader.php';
$user = new User(); $core = new Core();
require_once 'helpers/sl_view.php';
sl_gate('view_client_list');                 // login + permission, loads $permissions and $userData
require_once 'views/sl/data/customers.php';
sl_render('Customers', [
    'id'    => 'cust',                       // nav item id (helpers/sl_nav.php) to highlight
    'title' => 'Customers',
    'board' => 'Customers',                  // loads assets/swiftlane/pages/Customers.css
    // optional: 'primary' => ['href' => ..., 'label' => ...], 'theme' => 'dk', 'plain' => true,
    //           'scripts' => ['dataJs/sl/x.js'], 'wide' => true
], sl_customersData($user, $core));
```

Rules:

1. **Markup comes from the artboard.** Keep the design's structure, classes, copy and order. Replace demo values with `$d` values; replace demo lists with `foreach`. Add empty states with `.sl-empty`. Never add Bootstrap/legacy template markup.
2. **Escape everything** with `h()`. Only trusted pre-built HTML (SVG paths built in PHP) is echoed raw.
3. **No business logic in templates.** Queries live in the data provider; writes live in `ajax/sl/*_ajax.php` and reuse `helpers/querys.php` functions where they exist.
4. **Links** use `sl_route('Board', ['id' => $x])`. Legacy URLs that still exist keep working; add redirects for retired pages.
5. **Optional tables/columns** (anything created by a migration) are checked with `sl_tableExists()` / `sl_columnExists()` so a page never fatals on an older schema; show the empty state and say what the upgrade adds.
6. **Permissions**: gate pages with `sl_gate('perm')`, hide actions the user may not perform, and enforce the same permission in the endpoint (`require_permission`). Agency users are scoped with `cdp_getAgencyContext()`; customers see only `sender_id = $_SESSION['userid']`.
7. **Forms**: `<form data-sl-form action="ajax/sl/x_ajax.php">` posts via fetch with the CSRF token. Reply with `sl_json(['success'=>true,'message'=>..., 'redirect'=>...])` or `['success'=>false,'errors'=>['field'=>'msg']]` (HTTP 422). One-click actions: `<button data-sl-action="ajax/sl/x_ajax.php" data-p-id="5" data-sl-confirm="Sure?" data-sl-reload>`.
8. **Lists**: server-side search (`q`), filter (`filter`) and page (`page`) query params; render `sl_pager()`. Keep the design's segmented control as links that set `filter`.
9. **Toggles** `.sl-toggle[role=switch]` with `data-sl-save="ajax/sl/x_ajax.php" data-key="..."` persist on click.
10. **Audit**: call `cdp_activityLog([...])` after every write (module, action, summary, entity).
11. **Money/dates**: `sl_money()`, `sl_date()`, `sl_ago()`; never hardcode a currency symbol.
12. **Demo mode**: endpoints refuse writes when `CDP_APP_MODE_DEMO === true`.

## 3. Migrations

One file per feature: `migrations/2026_11_06_<topic>.sql`, same conventions as `2026_11_06_swiftlane_ui_core.sql` (SET NAMES; CREATE TABLE IF NOT EXISTS; column guards with information_schema + PREPARE; seed rows with WHERE NOT EXISTS; a ledger row; final SELECT). Never DROP or TRUNCATE. New permissions are inserted into `cdb_user_module_actions` with WHERE NOT EXISTS, then granted to roles 9 and 2.

## 4. Local run

```bash
cp config/config.example.php config/config.php   # edit DB settings
mysql -u root swiftlane < database/fresh_install_schema.sql    # or upgrade_existing_database.sql
php -S 127.0.0.1:8084
php scripts/dev_seed.php --i-know-this-is-a-dev-database      # sample data, dev only
node scripts/dev_shot.cjs http://127.0.0.1:8084/customers_list.php shot.png 1440 admin 'Admin123!'
```

Checks: `php -l` on changed files, `php vendor/bin/phpunit` (API tests), `node scripts/check_page_shell.js` only applies to legacy pages.

Design-system regressions: `node scripts/check_design_routes.cjs` checks every
literal `sl_route()` reference and its controller without a database.
`node scripts/check_design_runtime.cjs` runs the real shared CSS and JavaScript
against isolated local HTTP fixtures in Playwright/Chromium. It checks navigation,
dialog focus, table menus, filters, tabs, theme changes, password visibility,
switch rollback, validation, duplicate submissions, CSRF, and failed/expired requests.
It does not send messages, make payments, or use real user accounts.
